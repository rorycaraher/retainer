# Field-level merge for Note sync conflicts

Notes sync across an offline-first web app and Android app used by the same person on two devices, so concurrent edits during a network partition are an expected occurrence, not a rare edge case. We resolve sync conflicts at the field level — each Note field (title, color, pinned, etc.) and each Checklist Item merges independently, falling back to last-write-wins only when the exact same field or item was touched on both sides — rather than whole-note last-write-wins or a manual conflict-resolution UI. Whole-note LWW would silently discard concurrent edits to different parts of the same Note (e.g. checking off an item on the phone while renaming the title on the web), which is a data-loss failure mode that undermines trust in a notes app; a manual conflict UI is unnecessary complexity for a single-user tool with no real-time collaboration.

"Last write" per field/item is determined by a Hybrid Logical Clock (HLC) per device, not raw wall-clock timestamps. Edits happen offline with no server round-trip available, and a device with a skewed or manually-altered clock could otherwise cause a stale edit to silently "win" a merge — a hard-to-diagnose form of data loss. HLCs are the standard solution for ordering events in offline-first sync without requiring clock accuracy.
